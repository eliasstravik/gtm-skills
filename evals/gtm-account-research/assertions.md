# gtm-account-research assertions

1. **Critical:** Resolve the repo and target node by the shared contract and read exactly that node's own ICPs and personas plus its org chain.
2. **Critical:** State the GTM context and visible ICP/persona counts before research conclusions.
3. **Critical:** Ask no question or approval gate when inputs are complete.
4. **Critical:** Preserve supplied labels and never segment, change, repair, or reinterpret them.
5. **Critical:** Use supplied packets and web access when available, under link safety; unsafe sources appear only as a plain safe source label.
6. **Critical:** Separate inspected findings from unverified claims and tentative hypotheses while preserving publisher, date, and provenance.
7. **Critical:** Never silently join facts across sources, packets, or accounts.
8. **Critical:** Interpret fit, timing, risks, and personalization angles against visible prose.
9. **Critical:** Assign exactly one priority from `high`, `medium`, or `research-needed` with evidence-calibrated confidence and needs review.
10. **Critical:** Use the lean brief spine: executive brief, findings, fit, timing, risks, angles, recommended next step, priority block, sources.
11. **Critical:** Bulk output opens with a reconciled research-priority distribution.
12. **Critical:** A save request explains the org-only principle and renders the complete brief copyably in chat without writing.
13. **Critical:** When the target has no visible ICP, report the missing prerequisite and stop without borrowing, priority, or brief.
14. **Critical:** Make no filesystem, Git-history, repo, CRM, or external-system change.
15. **Critical:** Close exactly: `No files, git history, or external systems changed.`
16. Use capability language only and avoid old-model, promotion, or fixed-schema concepts.
